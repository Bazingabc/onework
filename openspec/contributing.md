# 参与共建

[返回 README](../README.md) · [开发指南](development.md)

OneWork 目前处于开发者预览阶段。欢迎从一个具体的使用障碍开始：安装是否清楚、卡点是否易懂、平板操作是否顺畅、换网和授权失败后是否知道该怎么办。

## 反馈问题

在 [GitHub Issues](https://github.com/Bazingabc/onework/issues) 提交问题时，可以复制以下内容：

```text
问题：
期望行为：
实际行为：
最小复现步骤：

OneWork 版本 / commit：
Mac 系统与芯片：
平板型号与 Android 版本：
Codex CLI 版本：
飞书 CLI 版本（若相关）：
连接方式：USB / 局域网
设备权限：查看 / 操作
两端版本是否同时更新：

脱敏截图或错误信息：
是否稳定复现：
已尝试的恢复步骤：
```

优先提供最短复现和错误类别，不需要上传完整环境或完整对话。任务名称、目录、设备编号等使用虚构值替代。

## 提交改动

1. 从当前仓库创建自己的工作分支，首次构建参见[安装指南](installation.md)。
2. 一次 PR 尽量解决一个问题。涉及新 Agent、接口协议、权限或数据迁移时，先发 Issue 对齐。
3. 修改对应模块并补上能覆盖原问题的测试；界面改动附 mock 数据截图。
4. 执行[开发指南](development.md)中与改动相关的验证，说明未验证项。
5. 提交 PR，写清问题、实现、影响范围、验证结果和兼容性影响。

推荐 PR 描述：

```text
解决的问题 / 对应 Issue：
主要改动：
用户可感知的变化：
验证命令与结果：
实机环境及结果（如有）：
未验证项 / 已知限制：
是否涉及协议、权限、数据迁移或签名：
截图（仅模拟数据）：
```

不要求贡献者使用特定 AI 工具；AI 辅助产生的改动也需要能够解释和验证。不要为了“测试变绿”删除操作保护、放宽权限或忽略错误。

## 提交前的隐私检查

- 不提交 `.env`、登录态、API Token、配对二维码、设备 Token、TLS 私钥、签名密钥或证书容器。
- 不上传 `~/.agent-views`、`~/.codex`、飞书配置目录、真实任务历史、原始数据库或完整诊断日志。
- 检查截图中的任务标题、消息正文、用户名、工作目录、设备编号和额度是否来自真实账户，优先使用[可复现的模拟截图](screenshots/README.md)。
- `local.properties`、`build/`、`dist/`、APK / AAB、应用 Bundle 和本地缓存不进入源码提交。
- `.gitignore` 只是第一道保护，不能阻止已跟踪文件或 Git 历史泄露；发布前仍需检查待提交 diff 和历史。

怀疑发现安全漏洞时，不要在公开 Issue 中附利用细节或凭证；先通过维护者提供的私密渠道联系。若仓库尚未配置此类渠道，只公开最少的联络请求，不公开敏感材料。

## 许可证状态

本仓库暂未提供 `LICENSE`。本文不替维护者选择许可证，也不承诺某一种开源授权；涉及分发、再授权或正式接受代码贡献的条件，应先由维护者明确。状态变更后需同步 README 和本页。
